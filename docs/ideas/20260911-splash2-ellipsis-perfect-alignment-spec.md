# スプラッシュ2 `…` 位置の完全揃え 仕様書

> 作成日: 2026-09-11
> ステータス: Draft
> 用途: /add-feature への入力

---

## 1. 背景・目的

- スプラッシュ2の3行メッセージで、`…` の表示位置がわずかにずれて見える。
- 現状は各行を個別フレームで構成しており、列幅計算が行単位になるため、見た目の縦揃えが不安定になる。
- `…` を3行で同一X座標に固定し、目視で「完全に揃っている」状態にする。

---

## 2. スコープ

### 今回含めるもの
- スプラッシュ2本文3行のレイアウト方式を見直し、`…` の列位置を共通化する。
- 既存文言・既存の強調色（マゼンダ）・強調太字を維持したまま、位置揃えのみ改善する。

### 今回含めないもの
- スプラッシュ1の挙動
- スプラッシュ2の表示時間（8秒）
- メイン画面のUI・解析ロジック

---

## 3. 機能要件

### 3.1 `…` の位置揃え
- [ ] 3行の `…` は、同一コンテナ内の同一グリッド列（例: column=2）に配置する。
- [ ] 行ごとに別フレームで列計算しない（行単位の列幅差を発生させない）。
- [ ] `…` のX座標は3行で一致すること。

### 3.2 レイアウト方式
- [ ] 本文3行は `table_frame` のような共通親フレームを用意し、`grid(row, column)` で管理する。
- [ ] 列構成は「箇条書き」「左項目」「…」「右説明」の4列とする。
- [ ] 左項目列（column=1）は `minsize` を固定し、右説明列（column=3）は可変とする。

### 3.3 表示維持
- [ ] 文言は現仕様のまま維持する。
- [ ] 強調キーワードの色・太字ルールを維持する。
- [ ] 背景色・フォントサイズ・余白感は現行仕様を維持する。

---

## 4. 技術的考慮事項（参考）

- 既存実装では `add_aligned_item()` が行ごとに `row_frame` を生成している。
- この方式だと `grid_columnconfigure()` が各行で独立するため、`…` が厳密には揃わないことがある。
- 対応方針:
  - 共通 `table_frame` を1つ作成し、その中に3行を配置する。
  - `table_frame.grid_columnconfigure(1, minsize=...)` を1回だけ設定し、全行で共有する。

---

## 5. 受け入れ条件

- [ ] 3行の `…` が目視で完全に縦一直線に揃っている。
- [ ] 文字化けが発生していない。
- [ ] スプラッシュ2の既存文言・強調表示が維持されている。
- [ ] 表示時間8秒・起動シーケンス（スプラッシュ1→スプラッシュ2→メイン）に回帰がない。
