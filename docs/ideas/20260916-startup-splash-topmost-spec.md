# 起動時スプラッシュ1/2＋メイン画面初期表示の最前面化 仕様書

> 作成日: 2026-09-16
> ステータス: Draft
> 用途: /add-feature への入力

---

## 1. 背景・目的

アプリ起動時に表示されるスプラッシュ画面1（ロゴ）およびスプラッシュ画面2（事前準備案内）が、他ウィンドウの背面に回る場合がある。  
また、スプラッシュ後に表示されるメイン画面も、初期表示時に背面へ回ることを避けたい。  
起動導線を確実に見せるため、2つのスプラッシュとメイン画面初期表示を最前面で表示したい。

## 2. スコープ

### 今回含めるもの
- スプラッシュ画面1を最前面で表示する。
- スプラッシュ画面2を最前面で表示する。
- スプラッシュ後に表示されるメイン画面の初期表示を最前面にする。
- 既存の表示時間・内容・順序（1→2→メイン画面）を維持する。

### 今回含めないもの（将来対応）
- スプラッシュデザイン変更
- 表示時間変更
- スプラッシュ統合/削除

## 3. ユーザーストーリー

- ユーザーとして、アプリ起動直後の案内画面と、その後のメイン画面が前面で表示されてほしい。

## 4. 機能要件

### 4.1 スプラッシュ1（ロゴ）
- [ ] 表示直後に最前面属性を有効化する。
- [ ] 表示中は他ウィンドウより前面に維持される。
- [ ] 既存の自動クローズ（約2秒）は維持する。

### 4.2 スプラッシュ2（事前準備）
- [ ] 表示直後に最前面属性を有効化する。
- [ ] 表示中は他ウィンドウより前面に維持される。
- [ ] 既存の自動クローズ（約8秒）は維持する。

### 4.3 実装ルール
- [ ] `attributes("-topmost", True)` を利用する。
- [ ] 必要に応じて `lift()` と `focus_force()` で前面表示を補強する。
- [ ] スプラッシュ終了後は後続メイン画面の表示を阻害しない。

### 4.4 メイン画面（初期表示）
- [ ] スプラッシュ2終了後に表示されるメイン画面は、初期表示時に最前面へ上げる。
- [ ] 初期表示後は通常運用を阻害しないこと（常時最前面固定にはしない）。

## 5. 非機能要件

- 可用性: 起動時に2つのスプラッシュが視認できること。
- 可用性: スプラッシュ後にメイン画面が初期表示で視認できること。
- 安定性: メイン画面表示や既存イベント処理に回帰がないこと。
- 互換性: Windows環境で最前面化が機能すること。

## 6. 技術的考慮事項（参考）

> このセクションは壁打ち時点のメモです。詳細設計は `/add-feature` 実行時に `steering/design.md` として生成されます。

### 現状実装（確認済み）
- スプラッシュ1: `root = tk.Tk()` + `overrideredirect(True)` + `after(2000, destroy)`
- スプラッシュ2: `info_root = tk.Tk()` + `after(8000, destroy)`
- いずれも `-topmost` 未設定
- メイン画面: 後段で `root = tk.Tk()` を再作成してUI構築（初期最前面化の明示処理なし）

### 実装アプローチ（案）
- スプラッシュ1/2作成直後に:
  - `window.attributes("-topmost", True)`
  - `window.lift()`
  - `window.focus_force()`
- メイン画面初期表示時に:
  - `root.attributes("-topmost", True)` を一時適用
  - `root.lift()` / `root.focus_force()` 実行後、通常運用へ戻す（`-topmost` を解除）
- 既存の `mainloop()` 構成は維持する（最小差分）。

## 7. 受け入れ条件

- [ ] スプラッシュ1が常に前面に表示される
- [ ] スプラッシュ2が常に前面に表示される
- [ ] メイン画面が初期表示時に前面に表示される
- [ ] 表示時間（1: 約2秒、2: 約8秒）が変わらない
- [ ] スプラッシュ終了後にメイン画面が通常どおり操作可能
- [ ] 文字化けが発生しない
