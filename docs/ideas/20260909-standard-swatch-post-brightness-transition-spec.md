# 標準色見本処理後の明度確定トリガー復帰 仕様書

> 作成日: 2026-09-09
> ステータス: Draft
> 用途: `/add-feature` 実装入力

---

## 1. 背景・目的

現状は、標準色見本処理後の復帰を `on_mouse_up` / `ButtonRelease` 系イベントに依存しているが、
実動作では「明度は設定されるのに通常モードへ戻らない」ケースが残る。

つまり、イベント到達だけではなく、**「明度確定完了」そのものを復帰トリガーにする**ほうが安定する可能性が高い。

目的は、**標準色見本の明度値が画面へ反映された直後に、強制的に通常モード（四角形 99）へ遷移**させること。

---

## 2. 現状整理（コード観点）

- 標準色見本処理は `set_mode_rect("14")` で開始。
- 明度設定は `calculate_brightness(..., value_key=="14")` 内で
  `insert_to_visible_entries(avg_list)` により画面反映される。
- その後 `white_Value / white_flag / white_Press` を更新している。
- この「明度反映完了」地点は、復帰判定の信頼できるフックポイントになる。

---

## 3. スコープ

### 3.1 実施すること
- 明度反映が成功した場合に、通常モード復帰を実行する処理を追加する。
- 復帰はイベントハンドラ依存ではなく、明度確定完了の事実に基づいて実行する。

### 3.2 実施しないこと
- 標準色見本の採色アルゴリズム変更。
- 多角形/円モードの仕様変更。
- 圧力換算ロジック変更。

---

## 4. 仕様（主案）

### 4.1 復帰トリガー
- [ ] `calculate_brightness` の `value_key == "14"` ブロック内で、
      `insert_to_visible_entries(avg_list)` と `white_flag=True` まで成功した時点を復帰トリガーとする。

### 4.2 復帰方法
- [ ] 新規関数 `transition_to_normal_mode_after_swatch()`（仮名）を追加。
- [ ] 本関数は `modevar.set(1)` + `set_mode_rect("99")` を実行。
- [ ] UI再入を避けるため、`root.after_idle(transition_to_normal_mode_after_swatch)` で遅延実行する。

### 4.3 実行条件
- [ ] `current_value == "14"` のときのみ実行。
- [ ] 明度候補 `avg_list` が空でない場合のみ実行（採色失敗時は遷移しない）。

### 4.4 多重実行防止
- [ ] `swatch_transition_pending`（仮名）フラグで重複遷移を防ぐ。
- [ ] 遷移完了時にフラグを解除する。

---

## 5. 受け入れ条件

- [ ] 標準色見本処理で明度が表示されたら、即座に通常モードへ戻る。
- [ ] ユーザーが `四角形モード` や `選択範囲クリア` を追加操作しなくてよい。
- [ ] 復帰後は通常の選択範囲作成が可能。
- [ ] 明度が取得できなかった場合は、無理に遷移しない（エラー時の誤遷移防止）。

---

## 6. 他の改善策（比較）

### 案A（推奨）: 明度確定トリガー復帰
- 長所: ユーザーが確認した「明度は設定される」事実に直接連動するため安定。
- 短所: `calculate_brightness` にUI遷移責務が増える。

### 案B: on_mouse_up 内で `set_mode_rect("99")` のみ単純強制
- 長所: 実装が最小。
- 短所: 既存で不発事象があるため、根本解決にならない可能性。

### 案C: 画面側タイマー監視（短時間ポーリング）
- 長所: 取りこぼしに強い。
- 短所: 実装が過剰で保守性が低い。

---

## 7. 実装メモ（/add-feature 引き継ぎ）

### 7.1 変更対象（想定）
- `src/PressureReader.py`

### 7.2 変更ポイント（想定）
- `calculate_brightness` の `value_key == "14"` ブロック
- 通常モード遷移ヘルパー追加
- 多重実行防止フラグ追加

### 7.3 注意点
- モード遷移を同期実行せず `after_idle` 経由にし、イベント処理中の競合を回避する。

---

## 8. テスト観点

- 標準ケース: 明度表示後に自動で通常モードへ戻る。
- 連続ケース: 2回連続実行でも固着しない。
- 失敗ケース: 明度抽出失敗時に誤遷移しない。
- 回帰確認: 通常四角形解析・多角形・円に影響しない。
