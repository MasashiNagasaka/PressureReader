# CSV必須化後のエラーメッセージ表示範囲 見直し仕様

> 作成日: 2026-09-15  
> ステータス: Draft  
> 用途: /add-feature への入力

---

## 1. 背景・目的

`c2p()` の CSV 必須化により、標準色見本処理中の「色見本未入力（例: brightness 02 is empty）」まで  
「sheet_setting.csv の設定利用に失敗したため、圧力変換を実行できません。」として警告表示されるようになった。  
この表示は既存運用の体感と合わず、ユーザーが「CSV設定が壊れた」と誤認しやすい。

目的は、エラーメッセージを原因別に正しく出し分け、既存の標準色見本処理フローの分かりやすさを回復すること。

## 2. スコープ

### 今回含めるもの
- `c2p()` で発生した例外の原因分類
- CSV設定エラーと入力不足エラーの表示メッセージ出し分け
- 標準色見本処理中の入力不足時は、CSV設定エラー文言を出さない制御
- 既存の「警告1回のみ表示（sheet_setting_error_shown）」方針の維持

### 今回含めないもの
- CSVフォーマット変更
- 色見本読取アルゴリズム自体の変更
- Excel出力ロジックの変更

## 3. ユーザーストーリー

- 解析担当者として、標準色見本の入力不足時に「入力不足」と分かる案内を受け、CSV故障と誤解せず再設定したい。
- 解析担当者として、実際にCSV設定が壊れているときだけCSVエラー表示を見たい。

## 4. 機能要件

### 4.1 例外原因の分類
- [ ] `c2p()` の例外を以下の少なくとも2系統に分類する:
  - 入力不足系（例: `brightness XX is empty`）
  - CSV設定系（CSV未読込、キー不整合、チャート不整合など）

### 4.2 メッセージ出し分け
- [ ] 入力不足系では、CSV失敗文言を表示しない。
- [ ] 入力不足系の表示は、ユーザーが対処できる文言にする（例: 「標準色見本の入力が不足しています」）。
- [ ] CSV設定系では、現行のCSVエラー警告を維持する。

### 4.3 既存挙動維持
- [ ] 返却値仕様（`-9999`）は維持する。
- [ ] `sheet_setting_error_shown` の1回表示制御は維持する。
- [ ] 標準色見本の状態ラベル更新（未設定/読取失敗表示）の既存挙動を壊さない。

## 5. 非機能要件

- 文字化けを発生させない（UTF-8で編集）。
- UIフロー（ボタン配置・遷移）に変更を入れない。

## 6. 技術的考慮事項（参考）

### 実装アプローチ案
- `c2p()` 内で `ValueError` の内容を判定し、入力不足系を先に分岐する。
- もしくは独自例外（例: `BrightnessInputError`）を導入して明確に分離する。
- 「CSV必須」方針は維持しつつ、警告文言のみ責務分離する。

### 影響範囲（想定）
- 変更: `src/PressureReader.py`（`c2p()` の例外処理）

## 7. 受け入れ条件

- [ ] 標準色見本未入力（例: 4LW 瞬間圧で 02 が空）時に、CSV失敗文言が表示されない。
- [ ] 同ケースで、入力不足を示す案内が表示される（または既存の失敗表示に統合される）。
- [ ] 実際にCSV読込失敗させた場合のみ、CSV失敗文言が表示される。
- [ ] 既存の計算結果（正常ケース）に回帰がない。
