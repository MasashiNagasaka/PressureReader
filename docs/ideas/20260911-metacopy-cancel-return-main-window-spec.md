# 解析条件コピー: CANCEL時にメインへ復帰 仕様書

> 作成日: 2026-09-11
> ステータス: Draft
> 用途: /add-feature への入力

---

## 1. 背景・目的

- 現在、`解析条件をコピー` ボタンの処理でファイル選択ダイアログを `CANCEL` すると、アプリ全体の処理が終了してしまう。
- ユーザー意図は「コピー処理を中断してメイン画面に戻る」ため、`CANCEL` は安全に処理中断し、アプリは継続する挙動へ修正する。

---

## 2. スコープ

### 今回含めるもの
- `解析条件をコピー` 処理内の `CANCEL` 時挙動の修正
- コピー元/コピー先の選択中断時に、アプリを終了せずメインウィンドウへ復帰
- 既存のコピー成功時処理は維持

### 今回含めないもの
- 解析条件コピーのUIレイアウト変更
- PNGメタデータの仕様変更
- 他ボタン処理の `CANCEL` 挙動変更

---

## 3. 現状と原因

- 対象関数: `src/PressureReader.py` の `metaコピ()`
- 現状コードでは以下の分岐で `exit()` を呼んでいる:
  - コピー元PNG選択ダイアログ `askopenfilename` を `CANCEL`
  - コピー先PNG選択ダイアログ `askopenfilenames` を `CANCEL`
  - （防御分岐）コピー元画像メタ情報が不正な場合
- `exit()` 呼び出しにより、Tkinterアプリ本体が終了する。

---

## 4. 機能要件

### 4.1 CANCEL時の挙動
- [ ] コピー元選択で `CANCEL` した場合、処理を中断してメインウィンドウに戻る。
- [ ] コピー先選択で `CANCEL` した場合、処理を中断してメインウィンドウに戻る。
- [ ] 上記いずれもアプリ本体は終了しない。

### 4.2 エラー時の挙動
- [ ] メタデータ取得に失敗した場合は、必要に応じて警告を表示して処理中断する。
- [ ] エラー時もアプリ本体は終了しない。

### 4.3 既存動作維持
- [ ] 正常系（コピー元選択 → コピー先複数選択 → メタコピー保存）は現状どおり動作する。
- [ ] 他機能（PNG読込、PDF変換、Excel出力など）に回帰を出さない。

---

## 5. 技術的考慮事項（参考）

- `exit()` を使わず、関数から `return` して処理を抜ける。
- キャンセルは例外扱いではなく、ユーザー操作として静かに中断する。
- 失敗時通知を入れる場合は既存の `messagebox` スタイルに合わせる。

---

## 6. 受け入れ条件

- [ ] `解析条件をコピー` でコピー元ダイアログを `CANCEL` してもアプリが終了しない。
- [ ] `解析条件をコピー` でコピー先ダイアログを `CANCEL` してもアプリが終了しない。
- [ ] `CANCEL` 後にメインウィンドウ操作を継続できる。
- [ ] 正常系コピーが従来どおり成功する。
- [ ] 文字化けが発生していない。
