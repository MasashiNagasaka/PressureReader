# PressReader v3.4.2 現行仕様（As-Is）

## 1. 対象
- 対象ファイル: `C:\nagasaka\AI\PressureReader\py\PressReader_v3.4.2.py`
- 版数: `version = "3.4.2"`
- 実装形態: 単一PythonファイルのTkinterデスクトップアプリ

## 2. 目的（現状）
- PNG画像の輝度値を圧力値（MPa）に換算して表示する。
- 選択範囲（四角形・多角形・円形）内の平均圧力と有効測定範囲面積を算出する。
- 解析条件（シート種別、色見本値、温湿度、px->mm換算値）をPNGメタデータに保存・復元する。
- 選択範囲の圧力マップをExcel（xlsx）出力する。
- PDFをPNGへ一括変換する。

## 3. 起動と初期化
- 起動時にスプラッシュ画面を表示後、メイン画面へ遷移する。
- メイン画面は左に画像キャンバス、右に操作パネル（スクロール付き）を持つ。
- アイコン画像や各種ボタン画像は `pr_images` 配下を利用する。
- 起動ディレクトリ直下の`*.png`を削除する初期処理がある。

## 4. 画面要素（右パネル）
- 解析条件:
  - シート種別（15種）:
    - `5LW 持続圧/瞬間圧`
    - `4LW 持続圧/瞬間圧`
    - `3LW 持続圧/瞬間圧`
    - `LLW 持続圧/瞬間圧`
    - `LW 持続圧/瞬間圧`
    - `MS 持続圧/瞬間圧`
    - `HS 持続圧/瞬間圧`
    - `HHS`
  - 色見本用エントリ（0.1〜1.5の一部を種別に応じて表示）
  - 温度[℃]、湿度[%]
  - スケーリング（mm/px）
- 操作ボタン:
  - 標準色見本処理
  - PNGに解析条件保存
  - 測定範囲可視化（ON/OFF）
  - 範囲選択形状（四角形・多角形・円形）
  - 選択範囲クリア
  - PDF=>PNG変換
  - PNGを開く
  - 選択範囲Excel出力
  - 解析条件をコピー
- 表示:
  - 検出値（MPa）
  - 圧力最大点スライダー（表示点数）

## 5. 画像読込とメタデータ
- `PNGを開く`でファイル選択し、作業ディレクトリへコピーして読み込む。
- PNGメタデータ `info` キーに `press{...}` 形式（17項目）があれば復元:
  - シート種別
  - 色見本値13項目
  - 温度、湿度
  - px->mm換算値
- メタデータがなければ手入力状態で利用可能。

## 6. 解析処理（現状ロジック）
- 中核換算関数は `c2p(brightness)`。
- シート種別ごとに:
  - 利用する色見本エントリ（before_values）を切替。
  - 基準圧力系列（after_values）を切替。
  - 温湿度から領域A〜Eを判定。
  - 領域別の標準チャート配列（多数の固定配列）を使用。
  - `scipy.interpolate.interp1d`で逆補間（輝度->圧力）・順補間（圧力->輝度）を実施。
- しきい値処理:
  - `press_Max` / `press_Min` を種別ごとに設定。
  - `white_Value` と `white_Press` で白領域・範囲外の扱いを制御。

## 7. 範囲選択モード
- 四角形:
  - ドラッグで矩形作成。
  - 平均圧力、測定範囲、面積情報を計算・表示。
- 多角形:
  - 左クリックで頂点追加、右クリックで確定。
  - 頂点移動・多角形移動に対応。
- 円形:
  - 作成、移動、ハンドルで半径変更に対応。
  - 右クリックで正円化。

## 8. 可視化
- `測定範囲可視化`がONの場合、しきい値に応じて色変換した画像を表示。
- `圧力最大点`スライダーで、範囲内の低輝度点（高圧側）をマーク表示。

## 9. 出力仕様
- Excel出力（xlsx）:
  - 選択範囲画素を圧力変換し、範囲外は `999` / `-999` / 空欄を使用。
  - シート名は`data`。
  - セル正方形化のため列幅・行高を調整。
- PNGメタ保存:
  - 現在の解析条件を`press{...}`文字列として`info`に保存。
- 解析条件コピー:
  - コピー元PNGのメタデータを複数のコピー先PNGへ上書き保存。
- PDF=>PNG:
  - 複数PDF対応。
  - Popplerを使って変換し、必要に応じて回転保存。

## 10. 現状の実装上の特徴
- グローバル変数に強く依存する構成（状態が分散）。
- `c2p` が大規模（1000行超）で、条件分岐と重複ロジックが多い。
- UI構築、イベント処理、演算、保存処理が単一ファイルに混在している。
