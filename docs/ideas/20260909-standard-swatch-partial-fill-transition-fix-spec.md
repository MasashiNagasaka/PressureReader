# 標準色見本の部分設定時に通常モードへ戻らない問題 修正仕様書

> 作成日: 2026-09-09
> ステータス: Draft
> 用途: `/add-feature` 実装入力

---

## 1. 背景・問題

標準色見本処理（`value_key=="14"`）で、明度欄が7個中5個だけ埋まるなど
**部分設定**になった場合、明度表示は更新されるが通常モードへ遷移しないことがある。

実測では「明度は設定済みなのに標準色見本モードに留まる」状態が発生する。

---

## 2. 原因仮説（コード観点）

`calculate_brightness` の `value_key=="14"` ブロックで、
次の順序になっている点が主因候補。

1. `insert_to_visible_entries(avg_list)`（ここで明度表示は更新される）
2. `white_Value = float(brightness_entry_01.get()) + white_Value2`
3. `schedule_transition_to_normal_mode_after_swatch()`

部分設定時に `brightness_entry_01` が空欄だと `float("")` で例外化し、
3. の通常モード遷移予約まで到達しない。

---

## 3. スコープ

### 3.1 実施すること
- 部分設定でも通常モードへ遷移できるよう、遷移予約を例外から独立させる。
- `white_Value` 計算を空欄耐性のある方式に変更する。

### 3.2 実施しないこと
- 標準色見本の採色アルゴリズム変更。
- 四角形/多角形/円の基本操作変更。

---

## 4. 仕様

### 4.1 通常モード遷移の優先
- [ ] `avg_list` が1件以上あれば、**先に** `schedule_transition_to_normal_mode_after_swatch()` を実行する。
- [ ] `white_Value` 算出失敗は遷移を止めない。

### 4.2 `white_Value` 算出の耐障害化
- [ ] `brightness_entry_01` が空欄の場合、以下の順で代替値を使う:
- [ ] 表示中明度欄のうち「数値が入っている最後の値」
- [ ] それも無い場合は既存 `white_Value` を維持（上書きしない）
- [ ] 例外を握りつぶすのではなく、計算不能時は更新スキップする。

### 4.3 `c2p` 呼び出し条件
- [ ] 温湿度が両方入力済みのときのみ `c2p(white_Value)` を呼ぶ（現仕様維持）。
- [ ] `c2p` 失敗時も通常モード遷移には影響させない。

---

## 5. 受け入れ条件

- [ ] 明度欄が全件埋まらなくても、1件以上更新できたら通常モードへ戻る。
- [ ] 明度欄が部分更新されたケースでモード固着しない。
- [ ] `brightness_entry_01` 空欄でも例外停止しない。
- [ ] 温湿度未入力時でも標準色見本処理が継続できる。

---

## 6. 実装メモ（/add-feature 引き継ぎ）

### 6.2 主な変更箇所
- `calculate_brightness(..., value_key=="14")` ブロック
  - 遷移予約呼び出し位置

## 7. テスト観点

- ケースA: 7欄中7欄設定 -> 通常復帰
- ケースB: 7欄中5欄設定 -> 通常復帰（今回の再現ケース）
- ケースC: `brightness_entry_01` 空欄 + 他欄設定あり -> 通常復帰
- ケースD: 温湿度空欄 -> 例外なし + 通常復帰
