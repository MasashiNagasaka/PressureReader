# スケーリング行レイアウト再設計（表示欠け・間隔異常の同時修正）仕様書

> 作成日: 2026-09-11
> ステータス: Draft
> 用途: `/add-feature` 実装用

---

## 1. 背景・目的
- 現状のスケーリング行はレイアウトが崩れており、以下の問題が同時発生している。
  - `pixmm_entry` の横幅不足により `0.017614` が途中までしか表示されない。
  - `pixmm_entry` の右に不自然な大きい空白があり、`mm/px` が直右に表示されない。
  - 結果として単位表示の視認性が悪く、誤認リスクがある。
- 小手先の `width/padx` 調整では再発しているため、行レイアウトを安定方式へ変更する。

---

## 2. スコープ

### 2.1 対象
- スケーリング行（`ｽｹｰﾘﾝｸﾞ` ボタン + `pixmm_entry` + `mm/px` ラベル）
- `src/PressureReader.py` の row=17 周辺UI定義

### 2.2 非対象
- スケーリング計算ロジック
- スケーリングダイアログ仕様
- 検出値/Excel出力ロジック

---

## 3. 仕様

### 3.1 スケーリング行を独立フレーム化
- `button_frame` の列配置に直接置く構成をやめ、row=17に「専用の1行フレーム」を配置する。
- そのフレーム内で、以下を左から順に配置する。
  1. `ｽｹｰﾘﾝｸﾞ` ボタン
  2. `pixmm_entry`
  3. `mm/px` ラベル

### 3.2 `pixmm_entry` の表示幅確保
- `pixmm_entry` は `0.017614` を欠けずに表示できる幅を必須とする。
- 目安として `width=10` 以上を確保する（最終値は画面確認で決定）。

### 3.3 単位ラベルの直右表示
- `mm/px` は `pixmm_entry` のすぐ右に表示する。
- `pixmm_entry` と `mm/px` の間の水平余白は最小限（例: 0〜2px）とする。
- 不自然な大きい空白を作る設定（列固定幅、過大 `padx`）は使わない。

### 3.4 既存動作維持
- `ｽｹｰﾘﾝｸﾞ` ボタン位置（row順）と操作フローは維持する。
- `pixmm_entry` の値設定・読込・保存動作は変更しない。
- スクロールバー表示有無で見え方が崩れないこと。

---

## 4. 技術的考慮事項（参考）
> 詳細設計は `/add-feature` 実行時に確定。

- 根本原因は、全体グリッド列に依存した配置で列幅計算が他ウィジェットの影響を受ける点。
- 専用フレーム内のローカル配置（`pack` またはフレーム内 `grid`）で、横並びの間隔を固定化する。
- 既存変数名（`button_pixmm`, `pixmm_entry`, `label_pixmm_unit`）は維持し、参照先を壊さない。

---

## 5. 受け入れ基準
- [ ] `pixmm_entry` に `0.017614` を入れても欠けずに全文字表示される
- [ ] `mm/px` が `pixmm_entry` の直右に表示される
- [ ] `pixmm_entry` と `mm/px` の間に不自然な大きい空白がない
- [ ] スクロールバー表示時/非表示時の両方で上記表示を満たす
- [ ] `ｽｹｰﾘﾝｸﾞ` ボタンの操作と値設定動作が従来どおり
- [ ] 文字化けが発生していない
