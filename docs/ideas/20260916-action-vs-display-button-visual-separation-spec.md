# 操作ボタンと表示項目の視覚分離 仕様書

> 作成日: 2026-09-16
> ステータス: Draft
> 用途: /add-feature への入力

---

## 1. 背景・目的

現行UIでは、実際に操作できるボタンと、表示専用の項目が同じボタン見た目で並んでおり、ユーザーが誤って「押せる」と解釈しやすい。  
誤操作・迷いを減らすため、操作要素と表示要素を見た目で明確に分離する。

## 2. スコープ

### 今回含めるもの
- 明度行（`1.5`〜`0.1`）の「表示専用UI」を、操作ボタンと明確に異なる見た目へ変更する。
- 既存の実ボタン（`標準色見本処理`、`PDF→PNG変換して開く`、`PNGを開く`、`選択範囲Excel出力` など）は現行デザイン方針を維持する。
- 視覚分離のルールを仕様として明文化する。

### 今回含めないもの（将来対応）
- 右ペイン全体の再レイアウト
- 文言変更以外の大規模UI刷新
- ダークモード対応

## 3. ユーザーストーリー

- ユーザーとして、どこが押せるUIでどこが表示専用かを一目で理解したい。
- ユーザーとして、明度値は「ラベル表示」であると認識でき、誤クリックによる混乱を避けたい。

## 4. 機能要件

### 4.1 表示専用項目の定義
- [ ] 明度行の左列（`1.5`〜`0.1`）は「表示専用」と定義する。
- [ ] 表示専用項目は、操作可能ボタンと同じスタイルを使用しない。

### 4.2 視覚分離ルール
- [ ] 操作可能要素: 現行の `ttk.Button` スタイルを維持する。
- [ ] 表示専用要素: `ttk.Label`（または専用表示スタイル）へ変更し、ボタン感を排除する。
- [ ] 表示専用要素にはホバー時の見た目変化を付けない。
- [ ] 表示専用要素は、周囲UIとの整合が取れる最小限の装飾（背景・余白）に留める。

### 4.3 配置・挙動
- [ ] 表示/非表示の切り替えロジック（感圧紙種類ごとの出し分け）は現行挙動を維持する。
- [ ] 既存の明度ステータス表示（未設定/設定完了/読取失敗）は現行挙動を維持する。

## 5. 非機能要件

- 可読性: 表示専用項目が読みやすく、押せるように見えないこと。
- 互換性: 解析フロー・明度入力・CSV設定読込・可視化処理に回帰がないこと。
- 保守性: 変更は明度行UIの部品型とスタイルに限定する。

## 6. 技術的考慮事項（参考）

> このセクションは壁打ち時点のメモです。詳細設計は `/add-feature` 実行時に `steering/design.md` として生成されます。

### 実装アプローチ（案）
- 対象箇所: `src/PressureReader.py` の `button_mihon_15`〜`button_mihon_01` 定義と、`all_buttons`/`brightness_slots` の参照箇所。
- `ttk.Button` から `ttk.Label` へ置換し、必要なら `DisplayValue.TLabel` 等の専用スタイルを追加する。
- `update_entries_and_buttons()` の `grid_forget()` / `grid()` 切替は、表示要素（Label）として同等に維持する。

### リスクと対策
- リスク: 既存コード変数名 `all_buttons` が実態とずれる。
  - 対策: `/add-feature` 実装時に `all_mihon_widgets` 等へ改名し可読性を確保する。
- リスク: ラベル幅が変わり縦位置がずれる。
  - 対策: `width`, `padx`, `sticky` を既存配置に合わせて微調整する。

## 7. 受け入れ条件

- [ ] 明度行（`1.5`〜`0.1`）が「押せるボタン」に見えない
- [ ] 操作可能ボタン群は従来どおり押下できる
- [ ] 感圧紙種類を切り替えても、明度行の出し分けと状態表示が崩れない
- [ ] 既存の標準色見本処理から解析までの動作に回帰がない
- [ ] 文字化けが発生しない
