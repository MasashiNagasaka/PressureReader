# 標準色見本デバッグ表示: 失敗キーも実測値を表示する 仕様書

> 作成日: 2026-09-15
> ステータス: Draft
> 用途: /add-feature への入力

---

## 1. 背景

現状は、色見本キーが取得失敗した場合に `failed-fallback` として `roi_mean` を表示している。  
この値は「そのキーの実測値」ではないため、例えば `0.1` が `0.3` より低く見えるなど、解釈しづらい。

---

## 2. 目的

- 取得失敗キーでも、`None` や単純平均ではなく、ROI由来の**実測値**をデバッグ表示する。
- 成功/失敗判定ロジック、UI表示（読取失敗）は変更しない。

---

## 3. 要件

1. 失敗キーのログ値は `roi_mean` ではなく、ROI内画素から算出した実測値を使う。
2. 成功キーの表示は現行維持（`[DEBUG] swatch brightness X.X = NN.NN`）。
3. 失敗キーのログには「実測由来値」であることが分かるサフィックスを付与する。
4. エントリー値への書き戻しは行わない（失敗キーは空欄維持）。

---

## 4. 仕様詳細

### 4.1 失敗キーの実測値定義

- 対象画素（重要）:
  - `candidate_pixels_raw = roi`（ROIの生画素）
  - **上限ガード（250）適用後ではなく、ガード外の画素（251〜255）を含める**
  - 目的: `0.1` など高明度側が失敗した場合に、実際の高明度値をデバッグで確認できるようにする
- 失敗キー `k` の実測値:
  - アクティブキー順（暗→明）での位置 `i` を使い、  
    `percentile = 100 * i / (n - 1)`（`n` はアクティブキー数）を計算
  - `observed_value = np.percentile(candidate_pixels_raw, percentile)`
  - 小数2桁で表示

### 4.2 ログ形式

- 失敗キー:
  - `[DEBUG] swatch brightness 0.1 = 247.32 (failed-observed-pctl)`
- 既存の `failed-fallback` は廃止する。

---

## 5. 期待効果と制約

### 期待効果

- 失敗時でも数値がキーに応じて単調に近い傾向になり、読取状態を解釈しやすくなる。
- `roi_mean` 固定表示より、キー別の実態に近いデバッグ値になる。
- `0.1` 失敗時でも、250で頭打ちにならず、251〜255を含む実測側の状況を把握できる。

### 制約

- 失敗キーは「領域未検出」なので、真の色見本領域平均を直接計測しているわけではない。
- 本仕様の値は「ROI統計からの実測推定値（percentile）」である。

---

## 6. 受け入れ条件

- [ ] 失敗キーで `None` が出ない。
- [ ] 失敗キーで `(failed-observed-pctl)` が表示される。
- [ ] 同一ROIで、失敗キー値が `roi_mean` 固定ではなくキー別に変化する。
- [ ] 既存の成功/失敗判定とUI表示に回帰がない。

---

## 7. 実装メモ（PressureReader.py）

- `insert_to_visible_entries` に `active_keys` と `candidate_pixels_raw(=roi)` 相当情報を渡す。
- 失敗キー出力時に、キーの順位から percentile を算出して値を表示する。
- `candidate_pixels_raw` は ROI が存在すれば空にならない想定。ROI空時のみ安全策として `0.00 (failed-observed-empty)` を表示する。
