# Excel出力時の自動ズーム調整（出力セル範囲全体表示）仕様書

> 作成日: 2026-09-14
> ステータス: Draft
> 用途: /add-feature への入力

---

## 1. 背景・目的

- Excel出力時、選択範囲が広いと初期ズーム倍率が高く、出力セル範囲の全体像を把握しづらい。
- 画像解析結果の確認効率を上げるため、Excelを開いた直後に「出力セル範囲の全体像」が見える倍率へ自動調整したい。
- 同じ解像度（1920x1080）・同じズーム倍率でも、ノートPCの実画面サイズ差により「小さすぎる / まだ収まりきらない」見え方差が発生する。

---

## 2. 実現可否（結論）

- **実現可能**。
- 既存で使用中の `openpyxl` だけで対応でき、追加パッケージは不要。
- `ws.sheet_view.zoomScale` を出力時に設定すれば、Excel起動時の初期ズーム倍率を制御できる。
- ただし、**実機ごとの体感表示（物理サイズ差）を完全一致させることは困難**。
  - `xlsx` に保存できるのは論理的なズーム倍率であり、物理インチ差そのものは吸収できないため。

---

## 3. 前提条件

- 対象PCディスプレイは **解像度** `1920 x 1080` 固定とする。
- ただし、ノートPCではOS表示スケール（125%/150% など）やExcelウィンドウ枠の影響で、実効表示幅は1920pxより小さくなる前提で扱う。
- 現在のExcel出力では列幅・行高さは固定値:
  - 列幅: `3.0`
  - 行高さ: `22.5`（`3.0 * 7.5`）

---

## 4. スコープ

### 今回含めるもの
- 出力セル範囲（`row_count x col_count`）に応じて `zoomScale` を自動算出し設定する。
- ズーム倍率は最小/最大の安全範囲（例: `10%`〜`400%`）にクランプする。
- 実機差を緩和するため、横幅不足が起きにくい保守側パラメータを採用する。
- 実測基準として「ズーム100%時に 16行×56列 が画面表示可能」を算出の基準に採用する。

### 今回含めないもの（将来対応）
- Excelウィンドウの実サイズ取得（OS/Excel連携）
- ユーザー設定でズーム倍率を手動保存する機能
- 実画面インチ情報を使った完全個別最適化

---

## 5. 機能要件

### 5.1 ズーム自動算出
- [ ] 出力範囲サイズ（行数・列数）から推定表示サイズを計算する。
- [ ] 実測基準（100%で16行×56列）を用いて、縦横が収まる倍率を算出する。
- [ ] 幅・高さ双方を満たすため `min(width_fit, height_fit)` を採用する。
- [ ] ノートPCで横幅不足が出るケースに備え、横方向に追加マージンを持たせる（幅優先の保守側調整）。

### 5.2 ズーム設定
- [ ] 算出した倍率を `ws.sheet_view.zoomScale` に設定する。
- [ ] 倍率は整数化し、`10`〜`400` の範囲にクランプする。
- [ ] 極端な縮小を避けるため、最小倍率の下限値を見直せる設計にする（将来調整しやすくする）。

### 5.3 既存挙動維持
- [ ] セル値出力、列幅/行高さ設定、ファイル保存処理は既存どおり維持する。

## 6. 技術的考慮事項（参考）

> このセクションは壁打ち時点のメモです。詳細設計は `/add-feature` 実行時に `steering/design.md` として生成されます。

### 6.1 実測基準（案）
- ズーム `100%` のとき、画面に表示可能な範囲を次の実測値とする。
  - 縦: `16` 行
  - 横: `56` 列

### 6.2 ズーム算出（案）
- 出力範囲を `row_count`, `col_count` とする。
- `zoom_h = 100 * 16 / row_count`
- `zoom_w = 100 * 56 / col_count`
- `zoom = floor(min(zoom_w, zoom_h) * fit_margin)`
- `zoom = clamp(zoom, 10, 400)`
- `fit_margin` は安全マージン（例: `0.95`）

### 6.3 補正方針
- 横幅不足が残る場合は `fit_margin` を下げる（例: `0.95 -> 0.92`）。
- 文字が小さすぎる場合は `min_zoom` を引き上げる（例: `10 -> 12`）。

### 6.4 リスク
- Excelの実ウィンドウ状態（最大化/非最大化、リボン表示状態、表示倍率の個人設定）で見え方差が出る。
- ただし「全体像を概ね把握しやすくする」目的には十分有効。
- それでも横方向が不足する場合は、`fit_margin` を追加調整する。
- 物理サイズ差に対しては、同一ズームでも可読性・見え方の主観差が残る。

### 6.5 実運用方針（案）
- 本機能の目的は「初期表示で全体像を把握しやすくする」ことに限定する。
- 体感の個人差（小さすぎる/大きすぎる）はExcel側の手動ズームで最終調整する前提とする。
- 必要に応じて将来、アプリ設定として「ズーム補正係数（例: 90%/100%/110%）」を追加する。

---

## 7. 受け入れ条件

- [ ] 小さい出力範囲では過度に縮小されない（可読性を維持）。
- [ ] 大きい出力範囲では初期表示で全体像を把握しやすい倍率になる。
- [ ] ノートPC環境で「横幅が少し足りない」事象が改善される。
- [ ] 同解像度でも実機差による見え方差が残ることを仕様上の既知制約として明記する。
- [ ] `ws.sheet_view.zoomScale` が出力ファイルに設定される。
- [ ] 既存のExcel出力内容（値・空欄・セル寸法）に回帰がない。
- [ ] 文字化けが発生していない。
