# 標準色見本0.1が255扱いになる問題の対策仕様書

> 作成日: 2026-09-15
> ステータス: Draft
> 用途: /add-feature への入力

---

## 1. 問題

- 0.1（最明度）領域は実際にはうっすら色があるのに、デバッグ上 `255` になり読取失敗することがある。
- 原因は、最明度側の判定に白背景（255）が混入し、代表値が白側へ引っ張られること。

---

## 2. 方針

- 最明度判定は `mean` 依存をやめ、**白飽和を除いた高明度統計**で判定する。
- 具体的には、最明度候補判定に `p99_nonwhite` を使う。

---

## 3. 仕様

### 3.1 最明度判定指標

- 各成分について以下を計算:
  - `nonwhite_pixels = region_values[region_values < 255]`
  - `p99_nonwhite = percentile(nonwhite_pixels, 99)`（空なら `None`）
- 最明度成分の選定は以下優先:
  1. `p99_nonwhite` がある成分同士で最大を選ぶ
  2. 全成分 `None` の場合のみ従来指標（`mean_initial`）へフォールバック

### 3.2 最明度専用緩和の適用先

- 既存の「最明度のみ面積緩和（2%）」および「最明度のみ再フィルタ上限緩和（+0.05）」は、
  上記 3.1 で選ばれた成分に適用する。

### 3.3 デバッグ表示

- 最明度判定ログに次を追加:
  - `mean_initial`
  - `p99_nonwhite`
  - `selected_by`（`p99_nonwhite` or `mean_fallback`）
- 失敗時ログの `failed-observed-pctl` は継続するが、併せて
  `failed-observed-pctl-nonwhite`（`roi < 255` の percentile）も出力可能とする。

---

## 4. 非対象

- 標準色見本以外の解析モード
- 圧力換算、Excel出力ロジック
- UIレイアウト

---

## 5. 受け入れ条件

- [ ] 0.1領域に色がある画像で、255固定にならず最明度として選ばれる確率が向上する。
- [ ] 他キー（1.5〜0.3）の並びに大きな悪化がない。
- [ ] 既存機能（点圧表示・範囲選択・Excel出力）へ回帰がない。
