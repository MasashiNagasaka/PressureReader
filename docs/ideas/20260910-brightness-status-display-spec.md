# 明度設定欄の非表示化＋状態表示改善 仕様メモ

> 作成日: 2026-09-10
> ステータス: Draft
> 用途: `/add-feature` 実装用

---

## 1. 背景と目的
- 現在は明度の具体的な数値が画面上で見えており、ユーザーが任意に変更できる。
- これを防ぎ、ユーザーには「設定の成否」だけを見せる運用に変更したい。
- 一方で開発・検証時に確認できるよう、内部値は `print` で確認可能にする。

---

## 2. スコープ
### 対象
- 解析条件エリアの明度設定欄（見本ボタン右側の表示）
- `標準色見本処理` 実行後の表示更新ロジック

### 非対象
- 圧力計算ロジック（`c2p`、平均計算など）
- 温度・湿度・スケーリングの入力UI

---

## 3. 仕様
### 3.1 表示ポリシー
- 明度の具体的数値はユーザー画面に表示しない。
- ユーザーが明度値を手入力で変更できないようにする。
- 画面には「状態テキスト」のみ表示する。
- ただし明度の内部設定値は保持し、既存の圧力計算・判定・出力ロジックで従来どおり利用する。

### 3.2 状態表示ルール
#### 初期状態
- 表示: `見本ボタン + 未設定`
- `未設定` は **青字 + 太字** で表示（目立たせる）
- 状態ラベルの背景色は白固定にしない。ラベル配置先パネルと同一色にする。
- 状態ラベルの枠線は表示しない（フラット表示）。

#### 感圧紙種類変更時
- ユーザーが感圧紙種類セレクトを変更したタイミングで、明度の内部設定値をリセットする。
- 上記リセットに合わせて、見本ボタン横の状態テキストは対象欄を `未設定` に戻す。
- `未設定` の表示スタイルは初期状態と同じ（青字 + 太字）。

#### 標準色見本処理後
- 設定成功欄:
  - 表示: `見本ボタン + 色見本 設定完了`
  - 文字色: 黒（通常）
- 設定失敗欄:
  - 表示: `見本ボタン + 読取失敗(やり直し)`
  - 文字色: **赤字 + 太字**（目立たせる）
- 上記いずれの状態でも、背景はパネル同色・枠線なしを維持する。

### 3.3 デバッグ表示
- `標準色見本処理` による範囲選択確定時、各明度欄の内部設定値を `print` 出力する。
- 出力はデバッグ用途のみ（GUIには数値を表示しない）。
- 出力例（形式案）:
  - `[DEBUG] swatch brightness 1.3 = 184.25`
  - `[DEBUG] swatch brightness 1.1 = None (failed)`

---

## 4. 実装方針（最小変更）
- 現在の `Entry` ベースUIを以下のいずれかで置換:
1. `Label` 化して状態文字列のみ表示（推奨）
2. `Entry` のまま `state='readonly'` + 数値非表示テキスト運用

- 既存の明度内部値は別管理（メモリ上）し、計算系はその内部値を参照。
- 既存の `update_entries_and_buttons()` に状態表示更新ロジックを追加。
- `insert_to_visible_entries(avg_list)` は「数値代入」ではなく「成功/失敗状態反映」に役割変更する。
- 既存の `c2p()` や関連計算が参照する明度値の取得経路を壊さない。
  - 方針A: 計算時参照専用の内部データ構造を新設し、計算系はそこを参照
  - 方針B: 既存 `Entry` は非表示値保持のため内部的に維持し、表示だけ状態ラベルへ分離
  - いずれかを採用し、既存コードとの整合を最優先とする

---

## 5. 受け入れ基準
- ユーザー画面上で明度の数値が見えない。
- ユーザーが明度値を直接編集できない。
- 初期状態は全表示欄が `未設定`（青太字）。
- 状態ラベルの背景がパネル同色で、白ベタ背景や枠線が表示されない。
- 感圧紙種類をユーザーが変更したとき、明度状態表示は `未設定`（青太字）へリセットされる。
- 標準色見本処理後、成功欄は `色見本 設定完了`（黒字）、失敗欄は `読取失敗(やり直し)`（赤太字）で表示される。
- 処理確定時に、各欄の内部明度値が `print` で出力される。
- 既存の圧力計算・選択範囲処理・Excel出力の挙動が変わらない。
- 既存の温度/湿度/明度前提チェックや `c2p` 呼び出し経路で、`ValueError` や参照先不整合が発生しない。

---

## 6. リスクと補足
- 既存コードは `Entry.get()` 前提が多いため、UI型変更時は参照先を慎重に整理する。
- 計算系の入力源を「表示UI」から「内部データ」に寄せると安定する。
- `print` 出力は将来ログレベル制御（debugフラグ）へ拡張可能にしておくと保守しやすい。

---

## 7. 次アクション
- 本仕様で `/add-feature` 実装を行う。
- 実装後に以下を確認:
1. 初期表示（未設定）
2. 標準色見本処理の成功/失敗表示
3. `print` 出力内容
4. 圧力計算・Excel出力の回帰なし
