# Python依存追加ルール（ホワイトリスト運用）

<!-- Python追加パッケージのホワイトリストに対応しました。2026-09-04 Auther=Hiroaki Iwata -->
Python依存関係を追加・更新・検証する場合は、本ルールを必ず遵守する。

## ホワイトリスト（唯一の参照元）

直接指定するPythonパッケージは、次のいずれかのホワイトリストに記載されている場合にのみ許可する。

- 全社許可: `.python_packages_list/ 配下の全体公開ホワイトリストファイル`
- 個別申請許可: `.python_packages_list/ 配下の個別申請ホワイトリストファイル`

上記2ファイルに記載のないパッケージを直接指定して追加・更新・インストールすることは厳禁とする。

## ホワイトリストファイルの改変禁止

`.python_packages_list/ 配下の全体公開ホワイトリストファイル` および `.python_packages_list/ 配下の個別申請ホワイトリストファイル` の改変は厳禁とする。

## 従属（推移的）パッケージ

ホワイトリストに記載された直接指定パッケージが解決する従属（推移的）パッケージは、個別のホワイトリスト記載を不要とし、インストールを許可する。

## 適用範囲

以下は直接依存の追加・更新として扱う。

- `requirements.txt`、`requirements-*.txt`、`constraints.txt`
- `pyproject.toml` の依存関係定義（`project.dependencies`、`optional-dependencies`、`tool.poetry.dependencies` 等）
- `Pipfile`
- `poetry.lock`、`uv.lock` などのロックファイルを更新する依存関係変更
- 新たな外部Pythonパッケージの import を伴う実装

## 必須手順

1. 追加・更新する直接依存パッケージ名を2つのホワイトリストと照合する。
2. 照合時は、空行および `#` で始まるコメント行を無視し、それ以外の行だけを許可情報として扱う。
3. 依存関係を追加・更新する変更では、照合結果を `.steering/<日付>-<機能>/design.md` の「依存ライブラリ」に記載し、`tasklist.md` に「ホワイトリスト照合」タスクを追加する。
4. 実装後およびレビュー時には、変更した依存関係定義ファイルと照合結果に矛盾がないこと、Pythonコード、およびホワイトリストファイルに変更がないことを確認する。

## 非掲載パッケージが必要な場合

- 全社承認プロセスまたは個別承認プロセスで、対象パッケージの追加を申請する。
- 本リポジトリ内のホワイトリストファイルを変更してはならない。承認が完了し、正式なホワイトリストへ反映されるまで、当該パッケージをプロジェクトへ追加・更新・インストールしてはならない。

## 補足

- このルールは `.claude/rules/workflow-guardrails.md` を補完する。
- 本ルールと他の文書に矛盾がある場合は、`CLAUDE.md` を優先する。

## 違反時の対応

ホワイトリスト外の直接依存、またはホワイトリストファイルの改変を発見した場合は、直ちに該当パッケージを強制アンインストールし、対象、対応内容、および違反理由をユーザーに提示する。

## Pythonホワイトリスト参照ルール（最優先）
- Python依存関係の追加・更新・検証を伴う場合は、必ず .python_packages_list/ ディレクトリを確認すること。
- **ファイル名を固定決め打ちしてはならない。** .python_packages_list/ 配下の実在ファイルを列挙し、参照対象を決定すること。
- .python_packages_list/ フォルダ、または参照すべきホワイトリストファイルが存在しない場合は、**そのまま処理を進めることを厳禁**とする。
- 上記不足がある場合は処理を停止し、**必ずユーザーに確認を取ってから**再開すること。
- 本節は、ホワイトリスト名の固定例示より優先して適用する。
